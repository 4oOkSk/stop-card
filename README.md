# Stop Card

按最近任务卡片管理 Android 后台。

正常页面跳转交给 Android。用户划掉最后一张卡片后，Stop Card 检查其他保护条件；保护全部结束后，模块调用 Android 的强行停止功能。停止处理由用户划卡或手动停止触发。

[下载 APK](https://github.com/4oOkSk/stop-card/releases) · [运行规则](docs/design.md) · [构建说明](docs/build.md) · [设备验收](docs/device-tests.md)

## 使用前确认

- 当前源码版本为 **0.4.2 开发预发布**，适配目标为 Android 17。
- 安装要求为 Android 17（API 37）或更高版本。更高版本仍需单独验证。
- 需要 Root、Zygisk，以及兼容目标系统的 LSPosed 或 Vector。
- 管理范围限定为主用户。

## 安装与启用

1. 从发布页下载并安装 APK。
2. 在模块管理器中启用 **Stop Card**。
3. 将作用域设为 **系统框架**。
4. 重启手机。
5. 打开 Stop Card，授予 Root 权限并完成引导。
6. 保持 **观察模式**，检查设置中的状态。详细信息见 **设置 → 诊断**。
7. 确认模块就绪后，开启 **卡片规则**，关闭 **观察模式**。

更新 APK 后，再次确认模块已启用，然后重启。

## 日常使用

| 需要完成的事 | 操作与结果 |
|---|---|
| 让普通应用继续运行 | 保留有效卡片。 |
| 停止普通应用 | 移除最后一张卡片。模块在其他保护结束后复核并强停。 |
| 让应用在无卡时继续运行 | 在应用页选择 **允许后台**。批量修改后，可点击提示中的 **撤销**。 |
| 查看应用为何运行 | 打开应用详情，点击 **查看原因**。 |
| 安装后打开、跳转、分享或登录 | 正常操作。页面启动遵循 Android 权限和后台启动规则。 |
| 使用桌面小组件 | 保留小组件。所属应用可在无卡时刷新，也可通过点击唤醒。 |
| 使用快捷开关或 VPN | 正常操作。模块保护已核验的系统绑定和当前 VPN。 |
| 临时停止管控 | 点击首页的暂停按钮。 |

重启后的历史卡片保持待激活状态，应用正常放行；实际打开页面后，模块更新卡片状态。

只有被模块成功停止的应用，才会收紧后台再启动。模块在已适配的进程创建入口复核后台请求，服务与冷广播使用原生记录的调用来源。重新打开页面后恢复使用。音乐、下载和通讯应用需要在划卡后继续运行时，可添加例外。

卡片许可使应用获得 Stop Card 的运行保护。**减少有卡应用回收**默认关闭；开启后优先保留最近使用的有卡应用，按内存余量分配保护。系统的前台状态和闲置冻结保持原生行为，内存紧张时增强保护自动减弱。设置中的诊断可查看当前保护和后台唤醒来源。

## 暂停与故障恢复

能打开管理界面时，先点击首页暂停。需要独立恢复入口时，进入 **设置 → 故障恢复** 安装恢复辅助。

已安装恢复辅助后，可通过有 Root 权限的 ADB 执行：

```sh
adb shell su -c 'sh /data/adb/stop_card_recovery/disable.sh'
```

此命令写入紧急停用标记。模块有响应时会暂停；下次系统进程启动时会跳过执行挂钩。

如果系统或框架失去响应，请在模块管理器中停用 Stop Card，然后重启。重新准备恢复辅助后，按界面提示检查暂停和观察模式。

暂停后，重新打开已被强停的应用以恢复推送。

## 数据与许可证

日志字段限定为包名、事件和原因。日志滚动保留 7 天，并限制容量。诊断信息包含运行状态，分享前请检查内容。
