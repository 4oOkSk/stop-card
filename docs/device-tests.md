# 设备验收

[返回首页](../README.md) · [运行规则](design.md) · [构建说明](build.md)

按改动涉及的许可、系统入口和生命周期选择以下验收项目；更换系统或模块框架时覆盖其适配能力。同一制品与环境的有效结果可复用。测试报告记录实际覆盖范围，未执行的项目标记为“未验证”。

## 准备环境

1. 记录 APK 版本、SHA-256、系统构建和模块框架版本。
2. 按[安装步骤](../README.md#安装与启用)启用模块。
3. 确认独立停用方法可用，再进行故障测试。
4. 安装测试包 A、B、C。构建命令见[构建说明](build.md#构建与检查)。
5. 打开测试包，并按需授予通知权限。
6. 先暂停模块，记录 Android 原生行为。再开启观察模式，最后进入执行模式。

测试包名为 `io.github.user4ooksk.stopcard.test.a`、`.b`、`.c`。这些包导出测试组件，只用于测试设备。

查看测试日志：

```sh
adb logcat -v monotonic -s StopCardFixture AndroidRuntime ActivityManager
```

每项记录操作时间、配置代次、能力状态、模块决策和接收端结果。发送端没有报错，不能证明目标已执行。

## 检查模块状态

1. 核对已安装 APK 的版本与校验值。
2. 确认状态中的系统进程 PID 与当前进程一致，心跳持续更新。
3. 确认 `ready=true`，配置代次与已应用代次一致。
4. 检查本次用例需要的能力。未安装的能力记为“不支持”。
5. 确认当前是观察模式还是执行模式，并记录暂停状态。

旧状态文件不能证明新系统进程已加载模块。

## 检查界面与例外

- 应用列表显示简短状态。详情展开后显示保护原因；未知状态不能显示为已停止。
- 批量添加或取消例外后撤销，确认只恢复本次改动。
- 批量修改后，再单独修改其中一个应用。撤销批量操作时，应保留后来的设置。
- 应用卸载重装后，旧撤销操作不能恢复原安装的例外。
- 设置首页不显示固定参数。诊断信息默认收起，故障恢复操作在二级页显示。

## 检查卡片

1. 从桌面打开 A。
2. 点击两次 `New document card`，创建两张文档卡片。
3. 先移除原始卡片，再依次移除两张文档卡片。
4. 核对有效卡片数按 3 → 2 → 1 → 0 变化。
5. 确认前两次移除后仍有卡片许可。
6. 确认最后一张移除后，无其他保护时才强停。

强停结果需同时核对进程和 Android 的 `stopped` 状态。进程消失本身不能证明发生强停。

补充检查：留卡并息屏 30 分钟；划卡后立即重开；在复核期间暂停。重开和暂停必须使旧停止任务失效。

## 检查跨应用操作

1. 从桌面打开 A，再通过按钮进入 B 的操作页面。
2. 在 B 中进入 C 的认证页面。
3. 从 C 返回 B，再从 B 返回 A。
4. 核对两次返回结果、服务绑定和销毁日志。
5. 确认 B 在服务销毁完成前仍受保护。
6. 确认操作结束后，临时保护释放。未被用户关闭的 B、C 交给 Android 管理，不应仅因无卡而强停。

优先测试实际用户入口。ADB 可补查其他调用身份，但不代替安装器、分享和登录的真实流程。模块不再要求触摸来源证明。

- 点击 `Open target from application context`，确认无返回结果令牌的 `NEW_TASK` 页面能打开。
- 点击 `Delayed application-context Activity (5 s, then press Home)` 后回桌面，对照 Android 原生后台页面启动结果。Stop Card 不追加否决。
- 从应用打开第三方安装器，安装专用测试包，再点击 Open。确认新应用直接打开，无需卡片历史、例外或特定来源身份。
- 分别检查链接、分享和登录入口。未实际执行的场景标记为未验证。

普通操作还需覆盖隐藏超过 30 秒的情况。实际绑定和组件存活时应继续保护；空闲操作释放后，只对已有用户关闭意图的目标复核。

- 从桌面打开测试应用，访问其同包组件，再划掉最后一张卡片。桌面不应成为普通操作来源，也不应因自身组件留下永久保护。
- 释放 Provider 引用、移除任务或结束目标进程后，确认原生对象复核会清掉旧操作记录。另保留真实绑定，确认超过隐藏超时仍受保护，解绑及服务销毁后才释放。

## 检查快捷开关与 VPN

1. 记录 VPN 初始状态。
2. 在目标应用无有效卡片时，展开快捷设置。
3. 确认磁贴可用。点击开启 VPN。
4. 重新展开面板，核对磁贴显示、原生 VPN 配置和应用的 VPN 保护原因。
5. 关闭 VPN，核对配置和保护原因撤销。
6. 确认全过程模块就绪，最后恢复初始 VPN 状态。

面板关闭后的缓存磁贴状态不能作为最终结果。

绑定生命周期还需检查：面板展开超过 30 秒；暂停期间建立绑定后恢复；关闭面板后的解绑与服务销毁。无关应用伪造 action 或包名，不应获得绑定许可。

## 检查桌面入口与小组件

1. 在 A 中点击 `Publish own launcher shortcut`。
2. 关闭 A 的卡片，从桌面长按 A 图标，选择 `Open probe`。
3. 确认应用打开，并获得卡片许可。
4. 在 A 中点击 `Pin own test widget`，确认添加测试小组件。
5. 关闭 A 的全部卡片，确认仍有 `app_widget` 保护原因。
6. 向该测试小组件发送更新广播。核对立即刷新和 5 秒后的自动刷新。
7. 点击小组件，确认同包 `PendingIntent` 能打开页面。
8. 移除本次创建的卡片和小组件。
9. 确认删除回调完成后，模块撤销小组件保护并复核其他许可。

只操作本次创建的测试卡片和小组件。保留其他桌面内容。

## 检查后台入口与生命周期

先确认未被模块停止的目标允许正常后台请求。再划掉目标最后一张卡片，等待模块成功强停，最后由已知后台测试应用请求该目标。不要用 Activity 被拒绝作为通过条件。

| 项目 | 通过条件 |
|---|---|
| Activity | 原生权限及后台启动限制生效，模块不追加拒绝；正常打开后旧限制撤销。 |
| Service、绑定、Provider | 仅限制已成功停止且无保护的目标。来自可见页面或有效会话的依赖请求可执行。 |
| 普通和代理通知 | 只对已停止目标收紧入口，尊重原通知设置。前台服务不出现异常循环。 |
| 广播 | 普通、异步、有序、多接收者、超时和原生跳过均能正确结束。 |
| Job、闹钟、PendingIntent | 分别核对未关闭、已停止和重新打开三种状态。来源未知时保守放行并延后复核。 |
| 服务销毁 | 最后一次解绑不提前释放服务保护。实际销毁完成后才复核。 |
| 开关同包依赖 | 绑定期间依赖正常执行，不以组件不匹配拒绝请求。 |

广播测试需核对 `broadcast_lifetime`。服务测试需核对 `service_finish` 和 `service_teardown`。每个接收者与整条广播记录都应正常释放，不能提前结束有序广播。

## 检查额外保活

1. 选择仍有许可的缓存进程，记录 PID 和原生 `oom_score_adj`。
2. 依次测试关闭保活、开启保活、暂停、恢复、观察模式和执行模式。
3. 核对值在原生 900–999 范围内时，开启保活可调整为 900。
4. 核对低于 900 的进程优先级不变。
5. 核对暂停、观察或许可撤销后，由系统恢复原生计算结果。

各阶段尽量使用同一 PID。进程重建后需重新记录基线。不要直接写入 `oom_score_adj`。

## 检查启动、恢复和长期运行

| 项目 | 通过条件 |
|---|---|
| 完整启动与系统进程重启 | 按当前进程启动阶段等待就绪。无服务初始化崩溃。 |
| 历史卡片与初始化关闭事件 | 不因历史卡片批量强停。状态可信后处理目标事件。 |
| 状态读取失败、签名不匹配 | 相关控制暂停，未确认配置不显示为已生效。 |
| 管理界面退出与重连 | 可信配置继续生效，重连不覆盖较新的系统配置。 |
| 独立暂停与恢复辅助 | 待执行停止取消，停用标记生效。恢复不自动进入严格执行。 |
| 安装身份和用户空间 | 重装后旧许可失效。主用户之外不执行管控。 |
| 状态文件写入 | 模块文件描述符不随写入次数持续增长。 |
| 内存压力与 24–48 小时运行 | 记录系统响应、崩溃、CPU、内存和耗电，区分系统回收与模块强停。 |

分屏、画中画、真实分享、登录、输入法和无障碍需各自记录结果。离线单元测试不能替代这些设备测试。

## 收尾与报告

1. 恢复测试前的设置和 VPN 状态。
2. 删除本次创建的测试卡片和小组件。
3. 卸载 A、B、C 测试包。
4. 归档本次结果、必要诊断和失败证据后，清理设备上的临时脚本及诊断副本。
5. 确认模块仍就绪，配置代次一致。

报告逐项标记“通过”“失败”“未验证”或“不支持”。失败项附最短复现步骤。公开报告使用脱敏摘要，不附连接信息、密钥或原始设备日志。
