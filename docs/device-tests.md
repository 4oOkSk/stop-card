# 设备验收

本清单对应 [设计书第 11 节](design.md#11-验收清单)。每项须单独记录设备结果；单次验收报告留在本地任务材料中，未覆盖的项目不据此视为通过。

## 准备

1. 使用可恢复的测试环境，先验证 Root、框架自身和独立停用入口。记录 Android 构建、框架版本、管理 APK 版本与 SHA-256；公开报告只使用脱敏摘要。
2. 框架仅启用 Stop Card 的“系统框架”作用域，重启后保持观察模式并核对配置代次。恢复辅助可选，单独验证它的心跳和恢复行为。
3. 构建并安装 `testbed` 的 A、B、C 三个 debug APK。它们故意导出跨包组件，仅用于本地测试，不含网络和付款功能。测试结束后卸载。
4. 分别打开三个测试包，允许测试通知。先暂停 Stop Card 执行相同步骤，记录 Android 原生限制；再观察、最后逐入口启用。某入口未挂接时记为未测或不支持。

```sh
./gradlew :testbed:assembleDebug
adb logcat -v monotonic -s StopCardFixture AndroidRuntime ActivityManager
```

测试包名为 `io.github.user4ooksk.stopcard.test.a`、`.b`、`.c`。按钮标明目标与延迟；点击延迟按钮后按 Home，让调用真正发生在后台。以接收端日志为交付证据，不能只看发送端没有报错。

## 用例与证据

| 编号 | 操作 | 需记录的结果 |
|---|---|---|
| C1 | 打开 A 后按 Home，留卡 30 分钟并息屏 | 模块未强停；若系统回收，另记回收原因 |
| C2、C3 | 打开 A，连续创建两张 New document card；退后台后依次删除原始卡及两张文档卡 | 有效卡数按 3 → 2 → 1 → 0 变化；仍有文档卡时维持卡片许可而非 uncertain，延迟通知及后台入口不降为观察放行；仅最后一张移除后复核强停，记录延迟、stopped 和 PID |
| C4、R3 | 划卡后立即从桌面重开，重复 100 次；另在复核中暂停 | 旧决策被取消；新会话仍能操作；暂停后无新拒绝 |
| C5、C6 | 分屏、画中画、锁屏；分别返回、Finish、Finish and remove task | 可见窗口不误杀；实际卡片与排除任务语义正确 |
| N1 | B 在前台注册延迟通知，退后台；对比留卡和无许可状态 | 通知是否在入队前拒绝；尊重原渠道与通知总开关 |
| N2 | B 将 A 设为代理，由 A 发 delegated notification；另启动 B 的前台服务 | 按 B 的许可判断；无服务崩溃、通知超时循环；代理自己的通知正常 |
| W1 | A 延迟启动／绑定 B 的 Service、发送广播和启动 Activity | 分别覆盖 B 已运行及冷启动；接收端日志与入口拒绝日志对应 |
| W2 | A 延迟查询 B 的 Provider、发送 PendingIntent；B 自行注册 Job／闹钟后退后台 | 返回值、连接解除、广播完成与系统超时正常；Job／闹钟区分注册和真正交付 |
| U1 | A 打开 B flow，B 认证到 C 再返回；对比页面关闭、服务结束和隐藏超过 30 秒 | 可见窗口与生命周期保护、短超时后的复核；记录共享任务和返回结果的实际表现 |
| U2、U3 | 真实分享／文件选择／相机／登录；对比可见操作和隐藏后的延迟操作 | 目标与组件、临时许可和超时复核；本版不确认应用内部结果回调完成 |
| E1、E2 | 改输入法／VPN／默认电话等；新装、同签名升级、卸载重装及多用户 | 模块无需界面存活即更新角色；旧安装例外失效；共享／隔离进程无法隔离时明确保护；其他用户显示未启用 |
| R1、R2、R6 | 重启后划历史卡、初始化中关闭任务、停止界面；制造读取失败或签名不匹配 | 不做初始化批量强停；保留关闭事件；未知状态暂停相关能力；配置重连不回退 |
| R4、R5 | 先独立暂停；再在可恢复环境模拟控制循环停滞及系统进程重启 | 监测阈值、正常重启不误报、下次挂接前锁停；关闭模块可恢复；无数据清空 |
| P1、P2 | 额外保活关／开对照，内存压力与 24–48 小时待机 | 进程存活、前台响应、CPU／内存／耗电及崩溃；不预填节电率 |

每项记录：版本、观察／执行模式、已挂接能力、操作顺序、目标包、事件时间、接收端结果、模块决策与最终状态。任何遗漏均保留“未验证”，异常附最短复现步骤。

## Android 17 适配回归

以下是 0.2.3 之后修复的复测要求；各分支的实际覆盖范围以设备报告为准：

测试包新增立即启动、三秒后自行停止的 Service（`onDestroy` 故意执行一秒）和三秒后 `goAsync().finish()` 的广播按钮。点击后可按 Home，结合 `Service destroy begin`／`Service destroyed`、`Broadcast async finish` 与模块流程记录，检查是否提前释放。

桌面入口使用 `Publish own launcher shortcut` 发布 `Open probe`，从桌面长按测试应用图标执行；使用 `Pin own test widget` 添加测试小组件。关闭测试应用的卡片后发送刷新广播，核对立即刷新及 5 秒后的自动刷新，再点击并仅移除本次添加的小组件。核对快捷方式打开的卡片、同包 PendingIntent，以及小组件添加和移除前后的保护原因。

| 修复项 | 操作与通过条件 |
|---|---|
| 状态文件写入 | 持续写入心跳、就绪状态和事件，检查系统进程的文件描述符数量。指向模块状态文件及已删除临时文件的句柄不得随写入次数持续增长；成功及失败路径均须关闭模块自行打开的描述符。 |
| 系统服务初始化 | 分别执行完整重启与系统进程重启，按本次系统进程的启动阶段等待完成；不得只依赖会跨进程重启保留的 `sys.boot_completed`。检查无服务初始化崩溃，控制循环恢复、签名验证通过、配置代次一致且 `ready=true`。 |
| 快捷开关绑定 | 无有效卡片时展开系统快捷设置，开关应可用且点击生效；面板保持展开超过 30 秒，服务不被模块提前停止。关闭面板后，等原生解绑与销毁完成，再按卡片、可见窗口、VPN 角色及其他许可复核。暂停期间绑定、恢复后仍保持展开也应正常。其他应用伪造开关 action 或调用包名不能获得许可，无关组件的后台启动仍受限制。 |
| VPN 角色 | 从快捷开关启动及停止 VPN，核对系统对 `BIND_VPN_SERVICE` 服务的实际绑定及主用户原生 VPN 配置。启用时显示所属应用的 VPN 保护原因，停用后撤销；公开网络能力隐藏所有者 UID 时，控制循环仍须保持就绪。关闭面板后的缓存开关状态不能代替重新展开后的显示。 |
| 开关依赖 | 测试绑定期间点击开关启动同包服务；同包 PendingIntent 能运行，无持久卡片许可。解绑后隐藏超过短超时，重复服务回调不能延长临时观察；其他包、其他安装身份、Job 和同步服务不因此放行。 |
| 桌面入口与小组件 | 从桌面长按快捷方式打开无卡应用；添加、无卡自动刷新、点击并删除小组件，检查小组件角色与最后一张卡关闭之间的竞争。保护原因准确，旧停止决策失效，移除后先完成删除回调再复核其他许可。不修改其他用户的许可。 |
| 广播生命周期 | `broadcast_lifetime=installed`；覆盖普通、异步 `goAsync()`、超时、多接收者及原生跳过。各接收者从实际 scheduled 状态分别登记，到终态再释放；广播记录另行保护到所有接收者终态，覆盖有序广播两次交付之间的空档。重复终态和未交付的跳过不应结束其他流程，不改变 Android 的交付结果与超时处理。 |
| Service 结束 | `service_finish=installed`、`service_teardown=installed`；对比解绑、`stopSelf()`、`stopService()`、未运行服务撤销和宿主退出。`bringDownServiceLocked` 安排实际销毁时不能提前释放；应在 `serviceDoneExecutingLocked` 的最终销毁执行完成后释放。最后一次解绑不撤销 Service 本身的执行保护，其他仍在运行的组件也继续保护。 |
| 用户操作来源 | `user_input=installed`；实际触摸执行 A → B → C → B → A，核对流程详情为 `active`，具体绑定决策不含观察标记。桌面、最近任务和通知直接打开不创建操作链；系统关键 Provider 不应产生额外流程。返回 A 且绑定与组件完成后，即使 A 仍可见，B、C 的临时许可也应结束。输入要求按下、抬起属于同一可见 Activity，核验 UID 和包名；有效期 1 秒、只关联一个目标包。该输入不激活目标的持久卡片，也不能被不同 UID、其他 Activity 或另一目标包复用。键盘、无障碍及无法核验的输入继续按具体目标观察放行，不能将这些路径记为已确认。 |
| 额外保活 | `extra_keep_alive=installed`；开／关、暂停、观察模式及划掉最后一张卡前后，核对缓存进程的实际 `oom_score_adj` 和系统进程状态。仅在原值 900–999 内调整到 900；原值低于 900 不动，撤销许可后由原生 OOM 重算恢复。继续执行 P1、P2 的压力与耐久对照。 |

广播生命周期改挂 `BroadcastRecord.setDeliveryState`（兼容三参、四参），不再依赖 Android 17 已更名的队列类，也不反射可能被裁剪的编译期常量。广播入口挂具体接收者的原生策略方法，排除入队预检；Android 17 保活在 `psc.OomAdjuster.applyOomAdjLSP` 应用计算结果前调整，保留旧 `ProcessStateRecord` 的回退，避免依赖可能被内联的小型转发方法或 setter。服务在最终执行完成后释放。上述挂接状态须由实际 ROM 报告，离线测试不代替实机结果。

## 独立停止干预

恢复辅助安装后，先验证以下入口，再进行故障测试：

```sh
adb shell su -c 'sh /data/adb/stop_card_recovery/disable.sh'
```

确认普通入口放行、待执行停止取消，重启后模块先读到锁停标记。若框架或系统无法响应，用已验证的框架停用途径恢复。重新准备辅助只保留暂停与观察模式，不自动恢复严格执行；已被强停的应用需重新打开。
