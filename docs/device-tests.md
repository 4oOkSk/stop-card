# 设备验收

[返回首页](../README.md) · [运行规则](design.md) · [构建说明](build.md)

按改动涉及的许可、系统入口和生命周期选择以下验收项目；更换系统或模块框架时覆盖其适配能力。同一制品与环境的有效结果可复用。测试报告记录实际覆盖范围，待执行项目标记为“待验证”。

## 准备环境

1. 记录 APK 版本、SHA-256、系统构建和模块框架版本。
2. 按[安装步骤](../README.md#安装与启用)启用模块。
3. 确认独立停用方法可用，再进行故障测试。
4. 安装测试包 A、B、C。构建命令见[构建说明](build.md#构建与检查)。
5. 打开测试包，并按需授予通知权限。
6. 先暂停模块，记录 Android 原生行为。再开启观察模式，最后进入执行模式。

测试包名为 `io.github.user4ooksk.stopcard.test.a`、`.b`、`.c`。这些包导出测试组件，只用于测试设备。

查看测试日志：

```sh
adb logcat -v monotonic -s StopCardFixture AndroidRuntime ActivityManager
```

每项记录操作时间、配置代次、能力状态、模块决策和接收端结果；目标执行成功以接收端结果为依据。

## 检查模块状态

1. 核对已安装 APK 的版本与校验值。
2. 确认状态中的系统进程 PID 与当前进程一致，心跳持续更新。
3. 确认 `ready=true`，配置代次与已应用代次一致。
4. 检查用例需要的能力。环境缺少的能力记为“能力缺失”。
5. 确认当前是观察模式还是执行模式，并记录暂停状态。

模块加载以当前系统进程的就绪状态和日志为依据。

## 检查界面与例外

- 应用列表显示简短状态。详情展开后显示保护原因；状态待确认时明确显示待确认。
- 批量添加或取消例外后撤销，确认只恢复本次改动。
- 批量修改后，再单独修改其中一个应用。撤销批量操作时，应保留后来的设置。
- 应用卸载重装后，旧撤销操作保持失效，新安装身份单独维护例外。
- 设置首页只展示可操作设置。诊断信息默认收起，故障恢复操作在二级页显示。

## 检查卡片

1. 从桌面打开 A。
2. 点击两次 `New document card`，创建两张文档卡片。
3. 先移除原始卡片，再依次移除两张文档卡片。
4. 核对有效卡片数按 3 → 2 → 1 → 0 变化。
5. 确认前两次移除后仍有卡片许可。
6. 确认最后一张移除后，所有其它保护结束时才强停。

强停结果同时以进程退出和 Android 的 `stopped` 状态为依据。

补充检查：留卡并息屏 30 分钟；划卡后立即重开；在复核期间暂停。重开和暂停必须使旧停止任务失效。

使用分屏或气泡后退出，再移除一张专用测试应用卡片。核对系统容器清理前后 `task_remove`、`user_task_close` 均保持 `installed`，模块仍就绪，测试应用的关闭判断正常。

## 检查跨应用操作

1. 从桌面打开 A，再通过按钮进入 B 的操作页面。
2. 在 B 中进入 C 的认证页面。
3. 从 C 返回 B，再从 B 返回 A。
4. 核对两次返回结果、服务绑定和销毁日志。
5. 确认 B 在服务销毁完成前仍受保护。
6. 确认操作结束后，临时保护释放。用户保持打开的 B、C 继续交给 Android 管理。

优先测试安装器、分享和登录的真实用户流程，ADB 用于补查其他调用身份。

- 点击 `Open target from application context`，确认返回结果令牌为空的 `NEW_TASK` 页面能打开。
- 点击 `Delayed application-context Activity (5 s, then press Home)` 后回桌面，确认 Stop Card 放行，最终结果与 Android 原生后台页面启动规则一致。
- 从应用打开第三方安装器，安装专用测试包，再点击 Open。确认全新安装且使用默认许可的新应用可直接打开。
- 分别检查链接、分享和登录入口，待执行场景标记为“待验证”。

普通操作还需覆盖隐藏超过 30 秒的情况。实际绑定和组件存活时应继续保护；空闲操作释放后，只对已有用户关闭意图的目标复核。

- 从桌面打开测试应用，访问其同包组件，再划掉最后一张卡片。确认桌面打开由卡片许可管理，同包组件的保护随所属应用许可结束。
- 释放 Provider 引用、移除任务或结束目标进程后，确认原生对象复核会清掉旧操作记录。另保留真实绑定，确认超过隐藏超时仍受保护，解绑及服务销毁后才释放。

## 检查快捷开关与 VPN

1. 记录 VPN 初始状态。
2. 在目标应用无有效卡片时，展开快捷设置。
3. 确认磁贴可用。点击开启 VPN。
4. 重新展开面板，核对磁贴显示、原生 VPN 配置和应用的 VPN 保护原因。
5. 关闭 VPN，核对配置和保护原因撤销。
6. 确认全过程模块就绪，最后恢复初始 VPN 状态。

最终结果以面板关闭后的原生解绑、服务销毁和目标应用状态为依据。

绑定生命周期还需检查：面板展开超过 30 秒；暂停期间建立绑定后恢复；关闭面板后的解绑与服务销毁。其它应用伪造 action 或包名时，确认绑定许可校验拒绝该请求。

## 检查桌面入口与小组件

1. 在 A 中点击 `Publish own launcher shortcut`。
2. 关闭 A 的卡片，从桌面长按 A 图标，选择 `Open probe`。
3. 确认应用打开，并获得卡片许可。
4. 在 A 中点击 `Pin own test widget`，确认添加测试小组件。
5. 关闭 A 的全部卡片，确认仍有 `app_widget` 保护原因。
6. 向该测试小组件发送更新广播。核对立即刷新和 5 秒后的自动刷新。
7. 点击小组件，确认同包 `PendingIntent` 能打开页面。
8. 移除本次创建的卡片和小组件。
9. 确认删除回调完成后，模块撤销小组件保护并复核其他许可。

只操作本次创建的测试卡片和小组件。保留其他桌面内容。

## 检查后台入口与生命周期

先确认模块停止记录为空的目标允许正常后台请求。再划掉目标最后一张卡片，等待模块成功强停，最后由已知后台测试应用请求该目标。通过条件按下表分别判断。

| 项目 | 通过条件 |
|---|---|
| Activity | 模块放行，原生权限及后台启动限制决定结果；正常打开后旧限制撤销。 |
| Service、绑定、Provider | 仅限制已成功停止且保护全部结束的目标。来自可见页面或有效会话的依赖请求可执行。 |
| 普通和代理通知 | 只对已停止目标收紧入口，尊重原通知设置。前台服务保持正常生命周期。 |
| 广播 | 普通、异步、有序、多接收者、超时和原生跳过均能正确结束。 |
| Job、闹钟、PendingIntent | 分别核对保持打开、已停止和重新打开三种状态。来源待确认时放行并延后复核。 |
| 服务销毁 | 最后一次解绑后继续保留服务保护，实际销毁完成后才复核。 |
| 进程创建 | 已成功关闭且保护结束的目标在创建进程前拒绝已知后台来源；服务与冷广播分别核对原生来源，页面、未知来源和受保护的共享 UID 保持正常行为。 |
| 开关同包依赖 | 绑定期间所属应用及已跟踪依赖正常执行。 |

广播测试需核对 `broadcast_lifetime`。服务测试需核对 `service_finish` 和 `service_teardown`。每个接收者与整条广播记录都应在各自实际执行完成后正常释放。

## 检查额外保活

1. 选择有有效卡片的主要 UI 缓存进程，记录 PID、原生计算分值、实际 `oom_score_adj` 和冻结状态。
2. 依次测试关闭保活、开启保活、暂停、恢复、观察模式和执行模式。
3. 核对原生计算值在 900–999 范围内时，预算内目标实际分值可调整为 700 或 800；诊断中的最近使用顺序、RSS 和保护档位一致。
4. 核对低于 900 的进程优先级沿用原值，原生前台身份和闲置冻结继续正常工作。普通子进程、无卡进程和身份待确认的进程保持原生分值。
5. 核对暂停、观察或许可撤销后，实际回收分值恢复为系统原生计算结果。

各阶段尽量使用同一 PID。进程重建后需重新记录基线。测试以只读方式观测模块对 `oom_score_adj` 的调整。

补充核对多应用数量与 RSS 预算、内存紧张时的减弱和撤销、PID 复用、用户强停，以及增强保护释放后恢复原生缓存回收。检查唤醒关系按来源与组件区分，应用重新安装后旧关系失效。

## 检查启动、恢复和长期运行

| 项目 | 通过条件 |
|---|---|
| 完整启动与系统进程重启 | 按当前进程启动阶段等待就绪，服务初始化成功。 |
| 历史卡片与初始化关闭事件 | 历史卡片保持待激活，状态可信后处理目标关闭事件。 |
| 状态读取失败、签名校验失败 | 相关控制暂停，待确认配置明确显示待确认状态。 |
| 管理界面退出与重连 | 可信配置继续生效，重连采用较新的系统配置。 |
| 独立暂停与恢复辅助 | 待执行停止取消，停用标记生效。恢复后由用户选择执行模式。 |
| 安装身份和用户空间 | 重装后旧许可失效，管控范围限定为主用户。 |
| 状态文件写入 | 重复写入后，模块文件描述符数量保持稳定。 |
| 内存压力与 24–48 小时运行 | 记录系统响应、崩溃、CPU、内存和耗电，区分系统回收与模块强停。 |

分屏、画中画、真实分享、登录、输入法和无障碍通过设备测试各自记录结果。

## 收尾与报告

1. 恢复测试前的设置和 VPN 状态。
2. 删除本次创建的测试卡片和小组件。
3. 卸载 A、B、C 测试包。
4. 归档本次结果、必要诊断和失败证据后，清理设备上的临时脚本及诊断副本。
5. 确认模块仍就绪，配置代次一致。

报告逐项标记“通过”“失败”“待验证”或“能力缺失”。失败项附最短复现步骤。公开报告仅包含脱敏摘要，原始证据保存在受限任务材料中。
